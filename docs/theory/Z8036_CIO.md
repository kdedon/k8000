# Z8036 CIO -- theory of operation

RTL: `rtl/k8036_cio/z8036_cio.sv` (one module, no submodules).
Sources cited: Z8036 Z-CIO product specification (1985 Data Book
pp.673-698), 1988 Z8000 Family Data Book pp.282-305, UM0109.

## 1. The chip

A Z-Bus peripheral with two 8-bit ports (A, B), a 4-bit port (C), three
16-bit counter/timers, pattern-match logic on ports A and B, four
handshake types and a five-source interrupt structure on the IEI/IEO
daisy chain. 48 registers behind a multiplexed 8-bit AD bus.

| pin | port | notes |
|---|---|---|
| AD7:0 | `ad_in`, `ad_out`, `ad_drive` | in/out/drive triplet |
| /AS, /DS, R/W | `as_n`, `ds_n`, `r_w` | `r_w` 1 = read |
| /CS0, CS1 | `cs0_n`, `cs1` | selected when /CS0 Low and CS1 High |
| /INTACK, IEI, IEO, /INT | `intack_n`, `iei`, `ieo`, `int_n` | `int_n` open drain at the pad |
| PCLK | `pclk_fall` | the falling edge as a one-master-clock pulse |
| PA7:0, PB7:0, PC3:0 | `p?_in`, `p?_out`, `p?_oe` | per-bit drive enable |
| -- | `clk` | board master clock |

No parameters. No reset pin: /AS and /DS Low together reset the chip.
REQUEST//WAIT and every handshake line are Port C pins.

## 2. Clocking and reset

Every flop runs on `clk`; one `clk` edge is one pin sample. The chip's
three time bases are edge detects on that clock:

| chip clock | seen as | clocks |
|---|---|---|
| /AS rise | `as_rise = !as_q && as_n` | port input sample, 1's catchers, pattern match, handshake step, /INT latch |
| /DS fall | `ds_fall = ds_q && !ds_n && as_n && !ds_spent` | register access, acknowledge |
| /DS rise | `ds_rise` | AD float, `ds_spent` |
| PCLK fall | `pclk_fall` (input pulse) | timer-mode counters (PCLK/2), external trigger in timer mode, deskew count, a handshake stalled by /WAIT |
| count input | `ct_clk_q` vs `ct_clk_in` | counter-mode counters: rise counts, fall samples trigger and gate |

/AS is the chip's clock for everything port-side (1988 DB p.301 Note 7;
1985 DB p.695 Note 1): with /AS stopped the ports, patterns, handshakes
and /INT freeze while the counters keep running. The strobes are used
raw, with no synchroniser inside the module; a board with asynchronous
strobes adds its own. The same holds for PA, PB and PC: the data book times
them only by setup to /AS and PCLK (pp.695, 697), so the board synchronises
any that are asynchronous to `clk`.

Next-state logic sees the current sample's edges combinationally, so a
/DS fall in the same sample as an /AS rise already reads the new port
sample, pattern flags and /INT latch (`smp_*_nx`, `pm_pmf_nx`,
`int_latch_now`), and a counter acts on a register written in the same
sample (`reg_post`: `mccr_p`, `md_p`, `tc_p`).

Reset:

| cause | signal | effect |
|---|---|---|
| /AS and /DS Low in one sample | `hw_reset` | registers 0, MICR = 01, pattern, handshake, sample, catcher and /INT state cleared, `owned` cleared |
| MICR bit 0 written 1 | same clears | as above, by software |
| while MICR bit 0 is set | `in_reset` | every register reads 0 (MICR reads 01); only MICR bit 0 is writable; /AS-clocked logic idles |
| either, until the bit is written 0 | `ct_off` | counters, count latches, `ct_perr`, PCLK/2 phase held 0 |

The port output registers `out_a/b/c` are data and survive reset; a
reset floats the pins by clearing MCCR. No flop has an asynchronous
reset; the strobe and count-input edge detectors run through reset. The
board applies the /AS+/DS reset at power-up.

## 3. Blocks

```
          ad_in  as_n ds_n r_w cs0_n cs1 intack_n
            |     |    |    |    |    |     |
        +---v-----v----v----v----v----v-----v----+
        | strobe capture                         |  as_ad, as_intack_n, owned,
        | as_q ds_q -> as_rise ds_fall ds_rise   |  ds_spent, hw_reset, cyc_reg
        +---+----------------+-------------------+
            | bus_wr/reg_wr  | rd_data -> ad_q, ad_drive_q -> ad_out, ad_drive
        +---v----------------+-------------------+
        | register file  regs[0:47]              |  cs_cmd, port_cs_wr, ct_cs_wr
        | out_a out_b out_c                      |
        +--+---------+----------+---------+------+
           |         |          |         |
   +-------v--+ +----v-----+ +--v------+ +v-----------------+
   | port     | | pattern  | | hand-   | | counter/timers   |<- pclk_fall
   | inputs   | | match    | | shakes  | | ct[0:2] ct_pre   |<- PB/PC live pins
   | smp_*    +-> pm_s1/s2 | | hs[0:1] <-> ct[2] (pulsed)   |
   | catch_*  | | pm_bits  | | hs_drive| | ct_latch ct_perr |
   +----^-----+ +----+-----+ +--+---+--+ +--------+---------+
        |            | IP       |IP |             | IP, ERR
   pa/pb/pc_in  +----v----------v---+-------------v---------+
                | interrupts: src_req src_elig src_idx      |<- iei
                | int_latch, IUS, src_vec/ack_vec           |-> int_n, ieo
                +-------------------------------------------+
   port outputs: out_* / hs.bf_d / ct.out -> polarity -> open drain -> p?_out, p?_oe
```

| block | state | datapath | driven by |
|---|---|---|---|
| strobe capture | `as_q`, `ds_q`, `as_ad`, `as_intack_n`, `owned`, `ds_spent`, `ad_q`, `ad_drive_q` | `cyc_reg` = `as_ad[5:0]` with RJA set, else `as_ad[6:1]` | /AS level, /DS edges |
| register file | `regs[0:47]` (none for 0D-0F, 10-15, 1F, read from `out_*`, the pins, the counters and the vector logic), `out_a/b/c` | `rd_data` mux; `cs_cmd` decodes the IUS/IE/IP command on D7:D5 | `ds_fall` |
| port inputs | `smp_a/b/c`, `catch_a/b/c` | `eff_in`: pin XOR polarity, OR the catcher on Special I/O input bits -> `in_a/b/c` | `as_rise` |
| pattern match | `pm_s1/s2[p]`, `pm_bits[p]`, `pm_frz`, `lpm_latch`, `lpm_valid`, `pm_perr` | per-bit match `m` from PM/PT/PP; `hit` by PMS | `as_rise` |
| handshakes | `hs_q[p]` (`hs_t` less PMF and IP, which come from the status register), `hs_drive`, `hs_mask`, `wait_stall` | `hs_as` (the /AS step) then `hs_fin` (the data access and deskew) | `as_rise`, `ds_fall`, `pclk_fall` |
| counter/timers | `ct[i]` (`ct_t`: `cnt run tcp out sq2 pclr`), `ct_latch`, `ct_perr`, `ct_pre`, `ct_out1_q`, `ct_clk_q`, `ct_trig_q`, `ct_gate_q` | `ct_trig` (load and start), `ct_end` (terminal count) | `pclk_fall`, count-input edges, `ct_wr` |
| interrupts | `int_latch`, the IUS/IE/IP bits in `regs` | `src_elig`, `src_idx`, `src_vec`, `ack_vec` | `as_rise`, acknowledge `ds_fall` |
| port outputs | none | data -> polarity -> open-drain gating -> `p?_out`, `p?_oe` | combinational |

Register addresses used by name in the RTL: MICR 00, MCCR 01, vectors
02-04, Port C polarity/direction/Special I/O 05-07, port and C/T
command/status 08-0C, port data 0D-0F, current counts 10-15, time
constants 16-1B, C/T modes 1C-1E, current vector 1F, Port A 20-27, Port
B 28-2F (mode, handshake, polarity, direction, Special I/O, PP, PT, PM).
Addresses 48-63 read 0 and ignore writes.

## 4. Operation

### 4.1 Register access

```
sample   /AS  /DS   action
  n       0    1    as_ad <= AD; as_intack_n <= /INTACK; owned <= !/CS0 && /INTACK
  n+1     1    0    as_rise (port-side step); ds_fall:
                      read : ad_q <= rd_data, ad_drive_q <= 1
                      write: regs[cyc_reg] <= AD (per-register rules)
  n+2     1    1    ds_rise: ad_drive_q <= 0, ds_spent <= 1
```

- The latch is transparent while /AS is Low and holds until the next /AS.
  CS1 and R/W are the levels at the /DS fall. No PCLK term anywhere on
  this path (AC rows 13/14/30).
- One access per /AS: `ds_spent` blocks any further /DS until /AS falls
  again.
- Back to back: the /DS rise and the next /AS fall may share a sample;
  the AD float is ordered before the /AS latch.

Writes with side effects:

| register | rule |
|---|---|
| MICR | in reset only bit 0 is written; writing bit 0 = 1 resets |
| port command/status | D7:D5 command via `cs_cmd`; IOE from D0; PMF, ORE, IRF read-only. Clearing IP is refused in OR-priority mode while the pattern still matches, and sets IP and ERR if an error is held (`pm_perr`) |
| C/T command/status | command via `cs_cmd`; RCC set-only (first set copies `cnt` to `ct_latch`; reading the count LSB clears it); GCB stored; TCB triggers; held `ct_perr` turns an IP clear into IP+ERR |
| port A/B data | fills `out_a/b`; a 0 written to a Special I/O bit clears its catcher; refused on a handshake port while PMF and IP are both set |
| port C data | D7:D4 write-protect D3:D0 |

Reads with side effects or substitution: command/status reads take the
live IP/PMF/ORE/IRF; the current-count registers read `ct_latch` while
RCC is set; a vector register reads with status while its source
requests and MIE is set; the current-vector register reads the highest
eligible source's vector or FF; Port C reads the sampled pins with D7:D4
as 1.

### 4.2 Bit ports

Input: `pa_in` is sampled into `smp_a` at each /AS rise, inverted by
Data Path Polarity, and on Special I/O input bits ORed into the 1's
catcher, which holds until software writes that bit 0. A data read
returns input bits from that path and output bits from `out_a`
(`port_read`; mode D7:D6 01 reads all input, 10 all output).

Output: `out_a` XOR polarity drives the pin. `pa_oe` is on for output
bits of an enabled port (MCCR PAE/PBE/PCE), off for a Special I/O bit
whose pin level is 1 (open drain). With EOE set a counter/timer output
replaces PB4, PB0 or PC0 ahead of the polarity stage.

A port whose mode D7:D6 is 11 is handled as a bit port; no
bidirectional handshake is built. Port Link Control (MCCR D3) is stored
and reads back; the linked 16-bit port is not built.

### 4.3 Counter/timers

Pins: C/T 1 on PB4 (out), PB5 (count), PB6 (trigger), PB7 (gate); C/T 2
on PB0-PB3; C/T 3 on PC0-PC3, same order. Inputs are read from the live
pins through polarity and the catchers (`pb_live`, `pc_live`), not the
/AS sample.

```
trigger (TCB write | external, ETE | C/T1 link)   ct_trig: cnt <= TC, run <= 1
        |                                          (a running counter only with REB)
        v
  count step: timer mode  -> every other pclk_fall (ct_pre)
              counter mode -> count input rise
     if pclr: out <= 0                 (pulse output ends)
     if tcp : cnt <= TC                (reload the step after terminal count)
     if run && GCB && (!EGE || gate) && link gate:
          cnt <= cnt - 1;  cnt was 1 -> ct_end, IP (or ct_perr if IP still set)
```

| item | behaviour |
|---|---|
| terminal count | `cnt == 1` before the step; TC = 0 gives 65,536 counts |
| `ct_end` | pulse: `out` High one count; one-shot: `out` Low (it went High at the trigger); square wave: `out` toggles, first half always reloads; continuous (C/SC) sets `tcp` and keeps `run` |
| timer-mode trigger/gate | trigger edge `ct_trig_q` and gate level taken at `pclk_fall` |
| counter-mode trigger/gate | sampled as the count input falls (`ct_gate_q`); the gate qualifies the next rise |
| link control, MCCR D1:D0 | 01: C/T 1 output (inverted) gates C/T 2; 10: its fall triggers C/T 2; 11: its fall is C/T 2's count |
| error | terminal count with IP set sets `ct_perr`; the IP clear then sets IP and ERR |
| CIP | reads `ct[i].run` |

A terminal count sets IP in `regs` on the same master clock; /INT
follows at the next /AS rise.

### 4.4 Pattern match (bit ports)

At each /AS rise `pm_s1 <= in`, `pm_s2 <= pm_s1`; the compare uses the
older pair, so a match appears one /AS after the input.

| PM | PT | bit matches when |
|---|---|---|
| 0 | 0 | masked |
| 0 | 1 | `pm_s2 != pm_s1` (any transition) |
| 1 | 0 | `pm_s1 == PP` (level) |
| 1 | 1 | `pm_s1 == PP && pm_s2 != PP` (the edge PP names) |

`hit` is all unmasked bits (PMS 01, AND) or any (PMS 10, 11). PMF
follows `hit`. IP is set on the first matching sample (PMF was 0); in
OR-priority mode (PMS 11) on every matching sample. A match while IP or
ERR is still set records `pm_perr` if IOE is set. With LPM (mode D0) the
matching input is frozen in `lpm_latch` and read back while IP is set.
`pm_bits` keeps the per-bit matches for the OR-priority vector;
`pm_frz` holds them from the acknowledge until IP clears.

### 4.5 Handshakes

Enabled when the port is on and its mode D7:D6 is 01 (input) or 10
(output). Data path: pins <-> Buffer (`bf_d`) <-> Input register (`inp`)
or Output register (`out_a/b`). Port C lines (Table 1, p.678):

| line | Port A | Port B, 2-wire | 3-wire (either) |
|---|---|---|---|
| RFD or /DAV out (`s.rd`) | PC3 | PC1 | PC3 |
| /ACKIN or DAV/DAC in | PC2 | PC0 | PC2 |
| REQUEST//WAIT out | PC1 | PC3 | PC1 |
| DAC out / RFD in | -- | -- | PC0 |

`hs_mask` marks the Port C bits the handshake owns (overriding the
direction register); `hs_drive` holds their levels; polarity and
open-drain still apply.

The handshake steps once per /AS rise (`hs_as`):

- **Ack edge hold.** Between steps an ack edge sets `pnd` and, on a
  fall, latches the port data in `ad`; the next step moves the ack by
  that one edge. Pulses shorter than an /AS cycle are not lost.
- **Input.** Ack fall with the Buffer free: `bf_d <= data`, `bf <= 1`,
  RFD drops. `hs_prop` moves Buffer to Input register when it is empty
  (and PMF&IP are not both set), compares the byte against a level
  pattern (`hs_cmp`), sets IRF and raises IP (`hs_raise`; with ITB only
  when two bytes are held, unless the byte matched). Strobed latches on
  every ack fall; interlocked waits for the ack rise (`aw`); 3-wire
  raises DAC and drops it as DAV rises.
- **Output.** Output register to Buffer when the Buffer is free
  (`obf`), compared on the way; /DAV falls once the deskew count `dsk`
  is 0 (DTE: `2*deskew + 2` PCLK falls) and, for 3-wire, RFD is High and
  DAC Low. The acknowledge edge (ack fall, or DAC rise for 3-wire)
  frees the Buffer, raises /DAV and raises IP. Single-buffered (mode D4)
  empties the Output register only when the byte is taken.
- **Pulsed.** C/T 3 is linked in: an input port's ACKIN pin fall (or an
  output port's internal /DAV fall) triggers C/T 3; its inverted output
  is the handshake's ACKIN (or drives the /DAV pin).

The data access (`hs_fin`, at `ds_fall`): reading an input port takes
`inp`, clears IRF and IP (after the second byte with ITB) and runs
`hs_prop` again; writing an output port clears ORE and IP.

REQUEST//WAIT (handshake specification D5:D3 as the RTL decodes it): 1
output /WAIT, 3 input /WAIT, 4 special REQUEST, 5 output REQUEST, 7
input REQUEST (1988 Z8000 Family Data Book p.319); 2 and 6 act as 0.
REQUEST is a registered level updated at the step
(`hs_ready`). /WAIT is combinational: Low while the CPU's /DS is Low on
the data register of a port that is not ready (`wait_stall`). During
the stall no /AS arrives, so that port's handshake steps on `pclk_fall`
(`hs_wclk`); when it turns ready `hs_rel` completes the held read or
write and /WAIT releases.

### 4.6 Interrupts and the daisy chain

Sources, highest first: C/T 3, port A, C/T 2, port B, C/T 1 (`src_idx`
0-4). A source requests with IE and IP set; it is eligible when neither
it nor a higher source is under service.

```
/AS rise : int_latch <= MIE && IEI && any eligible   (new pattern/handshake IP included)
           int_n = !int_latch
ack /AS  : as_intack_n <= 0;  ieo drops if int_latch
ack /DS fall, IEI High, int_latch, a source eligible:
           IUS[src_idx] <= 1;  NV clear: ad_q <= ack_vec, ad_drive_q <= 1
ack /DS rise: AD floats
next /AS rise: int_latch reloads (IUS now blocks it) -> /INT releases
```

`ieo = !DLC && iei && no IUS && !(acknowledge && int_latch)`.

Only a request latched at the acknowledge's /AS takes part: a source
that sets IP later cannot drop IEO or take the acknowledge, and reaches
/INT at the next /AS. The acknowledge does not need /CS0.

Vector (`src_vec`): the port or C/T vector register; with the source's
VIS bit set and NV clear, status replaces bits:

| source | bits | code |
|---|---|---|
| port, OR-priority mode | D3:D1 | number of the highest matching bit in `pm_bits` |
| port, otherwise | D3:D1 | ORE, IRF, PMF; 000 on ERR |
| counter/timer | D2:D1 | 00 C/T 3, 01 C/T 2, 10 C/T 1, 11 on ERR |

## 5. Timing and resources

| event | delay | arises from |
|---|---|---|
| AD driven on a read or acknowledge | master clock of the /DS fall | `ad_q`, `ad_drive_q` registered at `ds_fall` |
| AD float | master clock of the /DS rise | `ds_rise` |
| register write visible to counters, OE | same sample | `reg_post` forwarding; outputs combinational from `regs` |
| timer-mode count | 2 PCLK per count | `ct_pre` |
| terminal count -> /INT | next /AS rise (AC row 25) | `int_latch` |
| acknowledge -> /INT release | next /AS rise (AC row 23) | `int_latch` |
| pin -> pattern IP | second /AS rise after the pin changes | `smp`, then `pm_s1` |
| /DAV after the Buffer fills | `2*deskew + 2` PCLK falls with DTE, then the next step | `dsk` |

Fit (see [STATUS.md](../STATUS.md); Cyclone V 5CSEBA6U23I7, 48 MHz
target, slow corner): 1,260 ALMs, 906 registers, 59.3 MHz, setup slack
3.96 ns, no block RAM or DSP.

Critical path: the /AS-latched address `as_ad` -> `cyc_reg` decode ->
the write enable of a register bit (Port A polarity, `regs[34]`).

## 6. Inferred and assumed

Full rows with citations: [DECISIONS.md](../DECISIONS.md) and the
conformance ledger in [K8036_CIO_TESTS.md](../K8036_CIO_TESTS.md).

| item | status |
|---|---|
| one access per /AS; a repeated /DS does nothing | inferred; the data book does not decide it |
| a strobe edge and a PCLK fall in one sample | open; order is whatever the RTL evaluates, no vector has both |
| PCLK/2 phase after reset restarts Low | open |
| timer-mode trigger and gate act on the step they are seen (silicon samples half a count cycle earlier) | residual |
| EOE output passes through direction, polarity and open drain | interpretation |
| addresses 48-63 read 0 | interpretation |
| IEI gates the /INT latch at the /AS rise | read from the AC table (no IEI-to-/INT delay listed) |
| IUS set at the acknowledge /DS fall | as the data book; differs from the FPU, which acts at the /DS rise |
| a port status write in the sample of an /AS rise keeps the IP and PMF that rise sets, unless it clears IP | inferred |
| bidirectional mode (11) | not built |
| Port Link Control (MCCR D3) | not built: p.679 gives only the registers a linked port uses and the B-before-A access order, not when Port B's byte is buffered or latched against Port A's handshake |
