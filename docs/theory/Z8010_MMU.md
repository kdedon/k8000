# Z8010 MMU -- theory of operation

RTL: `rtl/k8010_mmu/z8010_mmu.sv` (one module). Page and AC numbers are the
Zilog Z8010 MMU Product Specification's (00-2046-03, pp.559-575).

## 1. The chip

The Z8010 sits between a Z8001 and memory. It holds 64 segment descriptors
(base, limit, attributes), turns the 7-bit segment number and the offset's
high byte into A23:A8, checks each access against the descriptor, and on a
violation suppresses the access (/SUP) and requests a segment trap (/SEGT).
The CPU programs it with Special I/O commands on AD15:8. A7:A0 bypass the
chip. A DMA device presents addresses under DMASYNC.

| pin | port | dir | note |
|---|---|---|---|
| CLK | `clk_in` | in | rising-edge pulse, one master clock wide |
| /RESET | `reset_n` | in | level |
| AD15:8 | `ad[7:0]` in, `data[7:0]` + `data_drive[7:0]` out | bidir | offset high byte, command code and data; drive is per line |
| SN6:0 | `sn` | in | |
| ST3:0, R/W, N/S | `st`, `r_w`, `n_s` | in | |
| /AS, /DS | `as_n`, `ds_n` | in | |
| /CS | `cs_n` | in | command select; also sets MSEN at reset |
| DMASYNC | `dmasync` | in | |
| A23:8 | `pa[15:0]` + `pa_drive` | out | 3-state as value and drive |
| /SEGT, /SUP | `segt_n`, `sup_n` | out | open drain as the resolved level: 0 = this chip pulls Low |

`clk` is the board master clock. No parameters. A board with several MMUs
ANDs the `segt_n` and `sup_n` levels and resolves AD15:8 per bit from
`data_drive[n]`.

## 2. Clocking and reset

Every flop runs on `clk`. Nothing is clocked from a pin; there is no CDC.

| chip event | seen as | used for |
|---|---|---|
| CLK rise | `clk_in` | SN sample (`sn_clk`), DMASYNC counters, the /SEGT release count |
| /AS fall | `as_fall = ~as_low_q & ~as_n` | cycle open (`addr_latched`), end of the previous PA drive |
| /AS Low | `as_open` | transparent latch: `latched_ad/st/rw/ns/cs_n` copy the pins each master clock |
| /AS rise | `as_rise = as_low_q & as_n` | latch closes; translation, checks, command and acknowledge decode (`as_cyc`) |
| /DS Low | `~ds_n` | command execute, identifier drive |
| /DS rise | `ds_rise = ds_low_q & ds_n` | PA, data and /SUP released; cycle closed |

`as_low_q` and `ds_low_q` store "was Low", so the power-up value 0 means
High. `clk_in` may be High every master clock. The strobes act
independently of CLK, as the AC table times them (#13/#14, #34/#35 to the
/AS rise; #18/#19 SN to CLK; #6-#9, #27, #33 to /DS).

Reset: `reset_n` is tested first in the state block, every master clock,
and gates every pin drive combinationally. The pin is asynchronous on the
chip; the board synchronises it to `clk`. It clears the control and status
registers and the cycle latches, and loads
`mode_reg <= {~cs_n, 7'b0}`: /CS Low at the last reset sample sets MSEN
(#37/#38). Descriptors, inhibit bits included, keep their contents: p.570
clears only Mode, Violation Type and DSC and leaves the rest undefined;
they are zero from power-up. `sn_clk`, `latched_ad/rw/ns/cs_n` and `pa_q` have no reset: each is
rewritten before its first use.

## 3. Blocks

```
 AD15:8 ST R/W N/S /CS ---> [/AS latch] --+
                              latched_*   |  x_ad x_st x_rw x_ns
 SN --(CLK rise)--> sn_clk ---------------+-> x_sn        (pins while /AS Low
 DMASYNC --> [DMA detect] dma_go ---------+               or in a dma_go clock)
                                          v
            sar --+              d_idx = (ST==3) ? sar : SN[5:0]
                  |                       |
                  v                       v
   [command port] ----write----> [descriptor store]  desc_bh/bl/lm/at  (MLAB)
     cmd, dsc, fld                desc_cpui/dmai      (flops)
        ^   |                             | t_base t_lim t_attr
        |   | rd_byte                     v
        |   |              [translate + check]  phys = t_base + x_ad
        |   |                 slv, viol, pww     pass = {0, SN, x_ad}
        |   |                     |       |
        |   |      REF/CHG write<-+       +--> pa_q / pa, pa_drive
        |   v                     v
      AD15:8 out <--id-- [violation + trap] viol_type viol_sn viol_off bcsr
      data, data_drive       trap_pending  ack_pending  ack_wait
                             sup_held  sup_instr_hold  isn  ioffset
                                  |
                                  v
                             /SEGT  /SUP
```

All of it is in one file: wires for the datapath, one `always_ff` for the
RAM write port, one `always_ff` for every other register, one `always_comb`
for the pins.

| block | state | datapath | driven by |
|---|---|---|---|
| strobe edges | `as_low_q`, `ds_low_q` | `as_fall`, `as_rise`, `ds_rise` | /AS, /DS |
| /AS latch | `latched_ad`, `latched_st`, `latched_rw`, `latched_ns`, `latched_cs_n`, `sn_clk`, `addr_latched` | `x_*` muxes: pins while `as_open` or `dma_go`, else the latch; `x_sn` is `sn` in a CLK-rise clock, else `sn_clk` | /AS, CLK rise |
| DMA detect | `dma_low[1:0]`, `dma_active` | `dma_go = clk_in & dmasync & dma_low[1]`; `dma_blk` keeps the CPU path off the latch | DMASYNC at CLK rises |
| descriptor store | `desc_bh`, `desc_bl`, `desc_lm` (8 bits), `desc_at` (6 bits: REF CHG DIRW EXC SYS RD), 64 words each, asynchronous read; `desc_cpui`, `desc_dmai` (64 flops each) | one read index `d_idx`, one write port `d_wa`/`f_we` | command writes, REF/CHG updates |
| translate + check | none | `phys`, `pass`, `x_pa`; `responds` (MSEN, URS, MST/NMS, memory status 8-D); `slv`, `viol`, `pww`, `dma_viol` | `x_*`, descriptor, `mode_reg` |
| violation + trap | `viol_type`, `viol_sn`, `viol_off`, `bcsr`, `viol_captured`, `trap_pending`, `sup_held`, `sup_instr_hold`, `isn`, `ioffset`, `ack_pending`, `ack_wait` | `trap`, `vbit`, `fatl`, `sww`, `req`, `vt_next` | `as_cyc`, CLK rises, /DS rise |
| command port | `mode_reg`, `sar`, `dsc`, `cmd_pending` | `cmd = latched_ad`; `fld`, `dsc_next`, `last_byte`; `rd_byte`, `rd_ok` | `cmd_start`, `cmd_exec` |
| pins | `pa_q`, `pa_drive_q`, `data_q`, `data_drive_q` | each output = "now" term OR its register | all of the above |

Why this shape:

- **One lookup.** Translation and command access never overlap, so the
  descriptor read, the write port and `d_idx` are shared; a command cycle
  (ST = 0011) indexes by `sar`.
- **Asynchronous-read RAM.** The descriptor must be read in the master
  clock that sees the /AS rise, and a DMA address is translated in the
  clock that samples it. A registered read would need the index a clock
  earlier. Four 64-word MLABs (1,920 bits) give that; the two inhibit bits
  stay in flops (commands 0x15/0x16 set all 64 at once).
- **Outputs follow the strobe in the same master clock.** Each pin is a
  combinational "now" term (`drive_pa`, `drive_low`, `segt_now`, `sup_now`,
  `rd_now`, `id_now`) ORed with the register that holds it afterwards. A
  CPU on the same CLK reads a valid PA at its next CLK rise even at one
  master clock per CLK.
- **The open latch.** While /AS is Low, PA is computed from the pins
  (`drive_low`), so A23:8 are driven from the /AS fall (#28). The /AS-rise
  clock decides again from the latched values and stores `pa_q`.

## 4. Operation

### Translation (memory cycle, no violation)

| master clock that sees | action |
|---|---|
| CLK rise (T1) | `sn_clk <= sn` |
| /AS fall | `addr_latched <= 1`; previous `pa_drive_q` cleared |
| /AS Low | latch copies the pins; if `responds`, `pa = x_pa` straight from pins and RAM (`drive_low`) |
| /AS rise | `as_cyc`; `drive_pa`: `pa_q <= x_pa`, `pa_drive_q <= 1`; checks run; a clean access writes REF (and CHG on a write) back to `desc_at[d_idx]` |
| /DS rise | `pa_drive_q`, `sup_held` cleared, `addr_latched <= 0` |

`x_pa = t_base + {8'h00, x_ad}` (A23:8; no carry in from A7:0 since the
base's low byte is zero), or `{0, SN, offset[15:8]}` with TRNS clear
(p.562 Fig 4, p.564). `responds` is MSEN, SN6 = URS, a memory status, and
with MST set N/S = NMS. A /DS rise and the next /AS fall may share a master
clock: the end-of-cycle clears are written first in the block, the new
cycle's sets later.

### Violation and segment trap

At the /AS rise, with TRNS set:

```
slv  = DIRW ? page < limit : page > limit
viol = CPUI | slv | (RD & write) | (SYS & normal) | (EXC & ~fetch)
pww  = ~viol & DIRW & write & page == limit          (write warning)
trap = drive_pa & translating & checked & (viol | pww)
```

On `trap`:

- `viol_type <= vt_next`: one flag by priority CPUIV > SLV > RDV > SYSV >
  EXCV > PWW, ORed in if a violation is already captured; FATL if one is
  captured and this is a violation or a normal-mode warning; SWW for a
  system stack write into the warning page with a flag already set.
- First capture only: `viol_sn`, `viol_off`, `bcsr = {00, N/S, R/W, ST}`,
  `viol_captured`.
- `trap_pending <= 1` unless FATL is already set, or SWW is and this is a
  system stack warning (`req`); the access that sets FATL or SWW traps.
  Once FATL is set, or this access sets it, no flag of the access joins
  VTR (`vt_next`); FATL alone is added. /SEGT =
  `trap_pending | segt_now`, Low from this master clock (#30).
- A violation (not a warning) sets `sup_held` (this cycle, to the /DS rise)
  and `sup_instr_hold`: every later memory cycle of the instruction is
  suppressed again at its /AS rise, until a first-word fetch (ST = 1101)
  clears the hold.

`isn`/`ioffset` copy SN and the offset at each first-word fetch until a
violation is captured. While a trap is pending the first-word fetch is not
checked (`checked`); other fetches are (p.565, p.569). PA is still driven
on a violation.

### Trap acknowledge (ST = 0100)

| event | action |
|---|---|
| /AS rise, MSEN set (`ack_start`) | `ack_pending <= trap_pending`; `ack_wait <= 3` |
| each CLK rise | `ack_wait` counts down; at the third, `trap_pending <= 0`: /SEGT released |
| /DS Low | AD line 8+ID driven: 1 if `ack_pending`, else 0 (`id_now`, `id_line`); other lines not driven |
| /DS rise | drive off; `ack_pending`, `ack_wait` cleared; a count still running clears `trap_pending` here |

A CLK rise in the same master clock as the /AS rise counts as the first.

### Commands (ST = 0011, /CS Low at the /AS rise)

`cmd_start` sets `cmd_pending`; `cmd_exec` fires in the first master clock
with /DS Low, once. `cmd` is the latched AD15:8.

| code | read | write |
|---|---|---|
| 00 | `mode_reg` | `mode_reg` |
| 01 | `sar` | `sar`; `dsc <= 0` |
| 20 | `dsc` | `dsc` |
| 02-07 | `viol_type`, `viol_sn`, `viol_off`, `bcsr`, `isn`, `ioffset` | -- |
| 08-0F | descriptor field at `sar` | same field; bits 1:0 = base / limit / attribute / whole, bit 2 = increment `sar` after the field's last byte |
| 11 | -- | clear VTR, capture, trap, suppress |
| 13, 14 | -- | clear SWW, FATL |
| 15, 16 | -- | set CPUI, DMAI in all 64 descriptors |

`dsc` steps base high, base low, limit, attribute; reads step it too. A
read drives `rd_byte` on all eight lines from the /DS fall (`rd_now`, then
`data_q`/`data_drive_q`) to the /DS rise; a code with no read value drives
nothing. A write takes `ad` in the execute clock. The first write to a
descriptor not written since reset zero-fills its other fields
(`f_we = 4'b1111`). Commands work with MSEN clear.

### DMA

`dma_low` counts DMASYNC-Low CLK rises, saturating at 2. DMASYNC High at a
CLK rise after two Low gives `dma_go`: the pins (SN included) are
translated in that master clock, the latch is loaded from them, PA is
driven. Checks use DMAI in place of CPUI and treat EXC as a violation; a
violation only sets `sup_held` (no /SEGT, no capture). The cycle
(`dma_active`) ends at its /DS rise, or at the next DMASYNC-High CLK rise
(the second High sample: the CPU has the bus), which releases /SUP and
leaves PA driven. A DMASYNC-Low CLK rise
with /AS High also ends it, so the next /AS cycle is latched; PA and /SUP then hold to
the /DS rise.

## 5. Timing and resources

External timing, in master clocks from the strobe edge as sampled:

| output | asserted | released |
|---|---|---|
| A23:8 | clock that sees /AS Low (0 clocks) | clock that sees the /DS rise, or the next /AS fall |
| /SEGT | clock that sees the /AS rise | third CLK rise of the acknowledge, or its /DS rise |
| /SUP | clock that sees the /AS rise | clock that sees the /DS rise |
| AD15:8 | clock that sees /DS Low | clock that sees the /DS rise |

The MMU adds no clocks to a bus cycle; the acknowledge count of three CLK
rises is the only counted interval.

Fit (2026-11-14, 5CSEBA6U23I7, 48 MHz target, boundary flops included;
[STATUS](../STATUS.md)): 447 ALMs, 338 registers, 0 block-memory bits, 0
DSP; descriptors in four MLABs. Fmax 71.8 MHz, setup slack 6.90 ns.

Critical path: an input pin flop, through the `x_*` mux, `d_idx`, the MLAB
read, the limit compare and `viol`, into the REF/CHG write port
(the REF/CHG write-back decided in the same clock as the lookup).

## 6. Inferred and assumed

Full tables: [DECISIONS](../DECISIONS.md) and the conformance ledger in
[K8010_MMU_TESTS](../K8010_MMU_TESTS.md).

| item | status |
|---|---|
| /SEGT released at the third CLK rise of the acknowledge (`ACK_RELEASE_RISE`) | inferred from Fig.12 p.570; AC #31 is CLK-referenced |
| write data taken in the first /DS-Low clock | the specification gives no edge |
| one VTR flag per access, by priority | the specification defines each flag separately |
| a SAR write clears `dsc` | open |
| reading a write-only or unlisted code drives nothing | open |
| SAR, descriptors and status registers reset to zero | undefined in the specification; this implementation's value |
| DMASYNC High at more than one rise inside a DMA cycle | outside the stated protocol; /SUP ends at the second |
| a DMASYNC-Low CLK rise with /AS High ends the DMA cycle's hold on the /AS latch | interpretation; p.572 draws DMASYNC Low by the T2 rise in a normal DMA cycle, but not what ends the hold |
| a command write wins over a REF/CHG update in the same master clock | one write port; a Z-Bus CPU never produces the overlap |
